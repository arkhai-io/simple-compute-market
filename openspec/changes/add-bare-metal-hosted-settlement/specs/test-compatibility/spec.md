## ADDED Requirements

### Requirement: Bare-metal hosted evidence proves prerequisites before deal behavior

Focused and protected suites MUST first prove that the exact shipped checkout provides the accepted runnable bare-metal buyer/storefront, shared composition seams, trusted selected-site scheduling, real durable fulfillment/result/recovery/teardown, and implemented expanded hosted consumer. A missing package/change, unpromoted permanent contract, completed task list without shipped behavior, verified-only path, fake/no-op provisioner, hard-coded resource, or synthetic access success MUST fail the lane and MUST NOT be replaced by mocks claiming whole-host acceptance.

#### Scenario: Buyer package is absent

- **WHEN** the qualified artifact set cannot start a public bare-metal buyer through the shared plugin/composition contract
- **THEN** the hosted whole-host lane fails as blocked before financial execution

#### Scenario: Fake fulfillment reaches the lane

- **WHEN** result/evidence is not backed by authoritative site allocation, lease, executor, and access state
- **THEN** the lane rejects it and does not count the deal as successful

### Requirement: Focused bare-metal hosted contracts cover owned boundaries

Deterministic tests MUST cover exact profile publication/omission, accepted seller/resource/deadline derivation, buyer-local selection and authorization, no physical work before funded status, selected-site/resource pinning, cross-mode refusal, idempotent allocation/lease/access, portable evidence privacy, pre-collection failure/reclaim exclusion, collection, restart, access revocation, teardown, quarantine, and capacity restoration. Shared conformance MUST cover `card.v1`, `us_bank_transfer.v1`, and `us_ach_debit.v1`, interactive fallback, delayed funding, expiry retrieval, duplicate delivery, and unknown acknowledgements without simulating provider claims.

#### Scenario: Funding remains delayed

- **WHEN** deterministic hosted outcomes keep bank transfer or ACH nonfunded through the accepted hold/deadline
- **THEN** tests prove no hold extension/replacement, capacity commitment/scheduling, allocation, or executor call, plus authoritative expiry retrieval and the exact hold-release/reclaim recovery outcome

#### Scenario: Restart occurs at every mutation boundary

- **WHEN** the process restarts after funding, reservation, allocation, executor completion, access grant, evidence publication, collection, revocation, or teardown
- **THEN** tests prove the same operation resumes with no duplicate host/payment/access action and no premature capacity publication

### Requirement: Protected whole-host lane proves real access and teardown

Release qualification MUST run one exact manifest-pinned ordinary hosted bare-metal deal over public buyer/storefront APIs and ordinary network boundaries using the signed hosted release, real Stripe test mode, authoritative site service, real bare-metal provisioner/executor target, and a disposable host or accepted isolated physical test resource. The lane MUST prove discovery, negotiation, exact option/profile selection, funding, no pre-funding allocation, selected-site reservation, host provisioning, buyer-authorized access retrieval, an authenticated action on the provisioned host, signed portable evidence, collection/reclaim outcome, restart recovery, lease expiry/termination, access failure after revocation, executor teardown, allocation release, and capacity republishing. It MUST separately attribute marketplace commit/artifacts, hosted manifest/client/image/source/workflow, site/provisioner/adapter artifacts, resource identity, and protected workflow run without retaining secrets or unrestricted access details.

#### Scenario: Happy-path whole-host lease completes

- **WHEN** the protected buyer funds a real disposable host and retrieves bounded access
- **THEN** an authenticated host action succeeds before expiry, signed evidence authorizes collection, access fails after revocation, teardown completes, and the same resource becomes available only after release

#### Scenario: Provisioning fails after funding

- **WHEN** the protected or controlled failure lane causes terminal provisioning failure before access-ready evidence
- **THEN** no collection occurs, exact reclaim recovery is proven where eligible, and the resource remains unavailable until authoritative teardown/reconciliation permits release

#### Scenario: External prerequisite is unavailable

- **WHEN** Stripe test mode, hosted release, physical target, site/provisioner authority, or protected workflow credentials cannot be used
- **THEN** the report records the exact requirement unavailable and does not substitute a simulated provider or local no-op host claim

### Requirement: Independent compatibility lanes remain intact

Existing bare-metal Alkahest and credential-free verified-only tests MUST remain independent from hosted whole-host evidence. Enabling hosted settlement MUST not require wallets for hosted-only roles, and disabling hosted settlement MUST preserve the prior bare-metal artifacts, publication, and behavior byte-for-byte where configuration migration declares no change.

#### Scenario: Hosted mechanism is disabled

- **WHEN** the migrated configuration preserves only the prior Alkahest or verified-only path
- **THEN** its existing focused and integration suites pass without hosted service, client, payer profile, Stripe, or hosted secrets
