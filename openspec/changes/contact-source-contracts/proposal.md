# Strict contact source contracts

Issue: https://github.com/arkhai-io/simple-compute-market/issues/222

## Why

Editable contact text must preserve one reviewed blurb. Accepted introductions need a frozen listing/machine projection, not registry reconstruction or machine JSON hidden in commercial terms. An unbacked declaration must not invent physical inventory identifiers.

## What changes

- Define a strict single-entry text profile of the existing bounded contact map; retain schema-version-2 review/finalize and identity envelopes.
- Add explicit `context_contract: "accepted-listing.v1"` eligibility to new contact profiles/options. Capture a typed bare-metal declaration and accepted non-access terms from immutable listing intent at acceptance, binding the digest into the new obligation.
- Admit declaration identity without machine/physical-host placeholders, while retaining site-backed invariants and old serialization.
- Publish sanitized machine-readable conformance vectors and exact downstream ownership boundaries.

No historical data migration, runtime delivery rewrite, real publication, or provider operation is included. Full seller configuration, exchange persistence/rendering integration, and operator inventory workflows remain separate work.
