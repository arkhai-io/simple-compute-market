## MODIFIED Requirements

### Requirement: External payment qualification names its target

External qualification MUST identify the actual payments target and consumer revision and check readiness before mutations. Unavailable external prerequisites MUST report blocked/unrun; a configured lane missing required settings or failing readiness MUST fail setup by name before scenarios. Neither MUST substitute another mechanism. Reports MUST use the three evidence classes owned by add-arkhai-payments-lane-double D6. Payment-service ledger, hold release and hold extensions, fees, top-ups, payouts, and provider recovery remain the payments service's evidence; cases and outcomes remain the dispute authority's.

#### Scenario: A lane qualifies proposed contracts

- **WHEN** any exercised authority surface uses kit-owned unpublished candidate bytes
- **THEN** the lane-double D6 class is Qualification against a proposed contract, not Qualification against the published contract or Live evidence

#### Scenario: Bare-metal qualification lacks hardware

- **WHEN** a disposable selected-site host is unavailable
- **THEN** local deterministic tests do not claim authenticated access, revocation, or physical teardown

#### Scenario: A configured payments run lacks a buyer credential

- **WHEN** a payments target is configured but the buyer's marketplace credential is not
- **THEN** the payment scenario fails naming the missing setting, before mutations rather than disguising a configured-target setup failure as an unavailable external prerequisite
