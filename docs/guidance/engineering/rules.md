# Rules

How written rules are kept when work conflicts with them, and when an exception to a
rule is expected rather than a failure to follow it.

## Amend a rule or comply

When work conflicts with a rule the repository owns, amend the rule first or make the
work comply; never record a private exception to it. A rule that is wrong is changed
where it is written, so every reader of the rule sees the change.

## When an exception is expected

Guidance a repository shares with others is changed by all of them, and does not fit
every repository that reads it. An exception to shared guidance is expected when the
guidance conflicts with a need the repository can state: a case the guidance leaves
open, which the repository selects, or a rule of the guidance, which the repository
overrides. The exception is declared, with its reason, beside the part of the
repository it applies to, where whoever works on that part reads it; it is never kept
privately or left as a note at one line of code.

## What an exception is not

An exception never stands in for amending a rule the repository owns: its own rule
that does not fit is amended. Holding the repository to more than a shared rule asks
is an ordinary rule of the repository, not an exception. A repository that declares
everything an exception has stopped following the guidance, which is what this rule
exists to prevent: an exception answers a need the shared rule cannot meet, and a
shared rule that fits no repository is proposed for amendment where it is shared.
